# Agent model routing

The Shopnoltd agent supports two model-selection modes:

- **Auto** selects only active models whose AI Model record has `capabilities.free_tier=true`.
- **Manual** uses the active model explicitly selected by the user.

When a selected model hits a provider quota, timeout, network failure, or transient upstream outage, the agent marks that model temporarily unavailable for 90 seconds and tries the next eligible free-tier model. A manually selected paid model may be used because the user explicitly chose it, but automatic fallback candidates remain free-tier models only.

## Configure free-tier eligibility

Open the administrator AI Models page and edit a model. Enable **Free-tier eligible for Auto mode** only when the provider/model is genuinely available without charge under the configured account's current terms and limits.

The bootstrap automatically marks model names ending in `:free` as free-tier eligible (for example, an OpenRouter model with that suffix). Other providers' free tiers are not inferred from provider names: an administrator must explicitly mark them. Free-tier eligibility is an operator classification, not a guarantee of unlimited availability or zero incidental provider charges.

## Routing details

- The agent reads the authenticated active model catalog from `/api/v1/inference/models`.
- LiteLLM model aliases use the provider-qualified `Provider name:model name` format generated by `model-catalog-sync.sh`.
- Auto mode never chooses a model without the explicit free-tier flag.
- Failover is attempted for HTTP 402, 408, 425, 429, 500, 502, 503, 504 and network/timeout failures. Invalid requests and authentication/authorization failures are surfaced instead of being silently hidden.
- Completed conversation/tool results remain in the current agent process history while the task switches models. This milestone does not yet provide durable recovery after an agent pod restart; durable task records and workspace persistence are separate work.

Provider API credentials remain in the existing server-side AI provider and LiteLLM configuration. They are not sent to the browser.
